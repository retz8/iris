function hasAdditionalControl(a: Finding, b: Finding) { if ( !b.taxonomy.cwe.length || !a.taxonomy.cwe.some( (cwe) => !b.taxonomy.cwe.includes(cwe), ) ) return false; return a.locations.some( ({ role, path }) => (role === "control" || role === "root_control") && !b.locations.some((l) => l.path === path) && !b.codeEvidence?.some((e) => e.path === path), ); }



Before scrolling: what does this do?

The Breakdown

  • What it does: Returns true when finding a reports a weakness class (CWE) that b lacks and also points to a security control in a file that b never mentions, either as a location or as code evidence.
  • Key responsibility: Deep scans run many Standard scans and merge their results. Before two reports collapse into one finding, this check (run in both directions) keeps them apart when one describes a second missing control, like authorization beyond a shared login check.
  • The clever part: It demands two independent signals before splitting: a different CWE and an untouched control file. Either alone could be two scans describing one bug differently, and if b has no CWE at all, it declines to judge rather than guess.
