The Breakdown

  • What it does: Fingerprints an incoming crawl request, drops it if an identical one was already seen, then pushes it onto an async priority queue as a (negated priority, counter, request) tuple, while mirroring it in a dict for checkpoints.
  • Key responsibility: It is the front door of Scrapling's spider engine: every link a spider yields passes through here, so this method decides crawl order, prevents revisiting pages, and keeps a snapshot of pending work so a paused crawl can resume.
  • The clever part: The counter does double duty. It breaks priority ties so heapq never compares two Request objects, and because the scheduler creates it counting down (step=-1) for depth-first crawls, the same tuple turns FIFO into LIFO.
