uint8_t LFULogIncr(uint8_t counter) { if (counter == 255) return 255; double r = (double)rand()/RAND_MAX; double baseval = counter - LFU_INIT_VAL; if (baseval < 0) baseval = 0; double p = 1.0/(baseval*server.lfu_log_factor+1); if (r < p) counter++; return counter; }



Before scrolling: what does this do?

The Breakdown

  • What it does: Increments an 8-bit access counter with a probability that shrinks as the counter grows: 1 / ((counter - 5) x lfu_log_factor + 1). Counters at or below the starting value 5 always go up; 255 never does.
  • Key responsibility: Redis calls it on every key access under the LFU eviction policies. Combined with a per-minute decay, the counter estimates how hot a key is, so when memory runs out Redis can evict the keys that are rarely used.
  • The clever part: Eight bits can only count to 255, yet with the default lfu_log_factor of 10 the counter reaches 255 only after about a million hits. Making increments rarer at higher values buys a logarithmic scale for free.

Project Context

From redis/redis — src/evict.c. Redis is the widely used in-memory data store behind caches, session stores, queues and leaderboards; when it runs as a cache with a memory limit, its eviction policy decides which keys are thrown away first.
