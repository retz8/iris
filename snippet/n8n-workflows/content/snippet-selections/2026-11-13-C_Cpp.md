### Repo 1

- file_path: faiss/VectorTransform.cpp
- snippet_url: https://github.com/facebookresearch/faiss/blob/main/faiss/VectorTransform.cpp#L405-L416
- scheduled_day: tue
- file_intent: Fast Walsh-Hadamard transform kernel
- breakdown_what: Applies the Fast Walsh-Hadamard Transform in place: for block sizes 1, 2, 4 and up, it replaces each pair (a, b) with (a + b, a - b), mixing every input into every output in n log n steps.
- breakdown_responsibility: It powers Faiss's HadamardRotation, a cheap stand-in for a random rotation matrix. Three rounds of random sign flips plus this transform spread a vector's energy evenly across dimensions before quantization, without storing or multiplying a d-by-d matrix.
- breakdown_clever: It never multiplies, only adds and subtracts, so each pass scales the vector's norm by sqrt(2) and three full transforms by p^(3/2). The caller skips per-pass normalization and fixes the scale once at the end with a single multiply.
- project_context: Faiss is Meta's open-source library for similarity search and clustering of dense vectors, used to search billions of embeddings and a building block for many vector search systems.

```cpp
static void fwht_inplace(float* buf, size_t n) {
    for (size_t step = 1; step < n; step *= 2) {
        for (size_t i = 0; i < n; i += step * 2) {
            for (size_t j = i; j < i + step; j++) {
                float a = buf[j];
                float b = buf[j + step];
                buf[j] = a + b;
                buf[j + step] = a - b;
            }
        }
    }
}
```

### Repo 2

- file_path: src/evict.c
- snippet_url: https://github.com/redis/redis/blob/unstable/src/evict.c#L292-L300
- scheduled_day: thu
- file_intent: Probabilistic LFU access counter
- breakdown_what: Increments an 8-bit access counter with a probability that shrinks as the counter grows: 1 / ((counter - 5) x lfu_log_factor + 1). Counters at or below the starting value 5 always go up; 255 never does.
- breakdown_responsibility: Redis calls it on every key access under the LFU eviction policies. Combined with a per-minute decay, the counter estimates how hot a key is, so when memory runs out Redis can evict the keys that are rarely used.
- breakdown_clever: Eight bits can only count to 255, yet with the default lfu_log_factor of 10 the counter reaches 255 only after about a million hits. Making increments rarer at higher values buys a logarithmic scale for free.
- project_context: Redis is the widely used in-memory data store behind caches, session stores, queues and leaderboards; when it runs as a cache with a memory limit, its eviction policy decides which keys are thrown away first.

```c
uint8_t LFULogIncr(uint8_t counter) {
    if (counter == 255) return 255;
    double r = (double)rand()/RAND_MAX;
    double baseval = counter - LFU_INIT_VAL;
    if (baseval < 0) baseval = 0;
    double p = 1.0/(baseval*server.lfu_log_factor+1);
    if (r < p) counter++;
    return counter;
}
```
